1. Executive Summary & Business Objectives

In retail and enterprise procurement supply chains, freight expenses represent a significant, variable portion of total landed goods cost. Inaccurate freight forecasting distorts quarterly budgeting, hampers product margin calculations, and leads to invoice payment disputes.

The objective of this case study is to build, validate, and deploy an end-to-end Machine Learning system that forecasts invoice freight cost using shipment volume, monetary value, order turnaround lead time, and price density. The solution comprises rigorous Exploratory Data Analysis (EDA), feature engineering, implementation of four distinct regression architectures, hyperparameter optimization with GridSearchCV, and deployment via an intuitive Streamlit web application.

2. Part 1: Data Acquisition & Preprocessing

Dataset Source: Extracted from internal SQLite database inventory.db, focusing on the vendor_invoice table containing 5,543 historical commercial invoice headers.

Key Exploratory Data Analysis (EDA) Findings:

  • Collinearity with Invoice Value: Invoice total dollar value (Dollars) exhibited an exceptionally strong Pearson correlation with Freight (r = 0.985). Shipment unit volume (Quantity) also demonstrated strong correlation (r = 0.947).
  • Distribution Skewness: Raw freight cost showed significant positive right-skewness (skewness ≈ 3.8). Typical orders incur $10 to $150 in freight, with rare enterprise shipments exceeding several thousand dollars.
  • Shipping Economies of Scale: Low-volume shipments (Quantity ≤ 56 units) incur a median shipping rate of $0.10 / unit, whereas bulk shipments (Quantity ≥ 1,008 units) incur only $0.04 / unit. This demonstrates a ~60% per-unit cost reduction for bulk logistics, justifying tree-based non-linear regressors.

Preprocessing Pipeline:

  1. Data Cleaning: Parsed InvoiceDate and PODate; removed records with missing date timestamps.
  2. Feature Engineering: Derived days_po_to_invoice (turnaround duration between PO creation and invoice receipt) and Price_per_Unit = Dollars / Quantity (monetary value density).
  3. Outlier Mitigation: Continuous features were capped using the Interquartile Range (IQR) rule ([Q1 - 1.5×IQR, Q3 + 1.5×IQR]) to avoid gradient distortions from extreme values.
  4. Train/Test Split & Scaling: Partitioned into 80% training (4,434 records) and 20% holdout testing (1,109 records), scaled via StandardScaler fitted strictly on training data.

3. Part 2: Model Implementation, Tuning & Evaluation

Four candidate regression algorithms were implemented individually to benchmark linear and non-linear model families, followed by hyperparameter optimization using 5-fold cross-validation.

Candidate Architectures:

  • Linear Regression: Ordinary Least Squares (OLS) baseline capturing linear elasticity between dollar volume and freight charges.
  • Decision Tree Regressor: Piecewise non-linear decision tree capturing volume break-points and discrete rate tiers.
  • Random Forest Regressor: Bootstrap aggregation (bagging) ensemble combining 60 randomized trees to suppress prediction variance.
  • Gradient Boosting Regressor: Sequential boosting ensemble iteratively fitting decision trees to negative gradient pseudo-residuals.

Hyperparameter Optimization:

GridSearchCV was executed on the Random Forest Regressor across 5 cross-validation folds optimizing RMSE. The optimal configuration identified was: n_estimators: 50, max_depth: 6, and min_samples_split: 5.

4. Part 3: Model Deployment using Streamlit

The production deployment script app.py builds an interactive web portal using the Python streamlit library.

Core Deployment Features:

  1. Model Preparation: All trained models and feature scalers are serialized using joblib and cached into memory with @st.cache_resource for instantaneous inference response times.
  2. Model Selection Widget (st.selectbox): Allows procurement and finance officers to select any specific candidate model (Linear Regression, Decision Tree, Random Forest, Gradient Boosting, Random Forest (Tuned)) or run All Models (Compare All) simultaneously.
  3. Intuitive Feature Inputs (st.slider): Interactive sliders for Total Invoice Dollars ($100 – $100,000), Shipment Quantity (1 – 10,000 units), and Turnaround Lead Time (0 – 60 days).
  4. Real-Time Prediction (st.button('Predict')): Generates immediate forecasts displaying the predicted dollar amount, shipping cost proportion (% of invoice), per-unit freight overhead, and a comparative multi-model forecast grid.
  5. Cloud Deployment: Deployed live to Streamlit Cloud at https://invoiceanalysis3304.streamlit.app/ for global browser accessibility.
